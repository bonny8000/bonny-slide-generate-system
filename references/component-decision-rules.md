# Component Decision Rules

Choose the component by content intent first, then choose mode and color.

## Research Context / Background

Use when explaining why the problem matters.

- Use headline + 2-3 evidence cards for light mode.
- Use chart card + explanatory text when one statistic is the anchor.
- Use photo background + translucent cards when the topic benefits from human context.
- Use blue for general data/research, green for growth/service improvement, orange for cost/stress/attention.

Avoid: abstract decoration that does not explain the evidence.

## Desk Research / Survey Evidence

Use when showing quantified findings.

- Use three cards in a row, each with one chart or metric.
- Use donut/pie only for one dominant proportion.
- Use bar charts for comparison across categories or time.
- Use a full-width key insight band when the data needs a final takeaway.
- Use small source captions inside or under the card.

Avoid: putting raw tables on slides unless the user asks for audit/detail.

## User Research / Interview

Use when showing qualitative findings.

- Use quote cards, speech bubbles, or interview cards.
- Use participant tags and metadata when credibility matters.
- Use 2-column positive/negative cards for user test feedback.
- Use dark mode when the interview findings are emotional, critical, or need cinematic focus.
- Use light mode when the interview output is part of a structured research report.

Avoid: making every quote visually equal. Emphasize the repeated pain or insight.

## Problem / Pain Point

Use when defining what is wrong.

- Use pain cards with a short title, quote, and cause.
- Use red/pink only for actual warnings, friction, or negative findings.
- Use avatar/emoji-style markers only if the slide is portfolio-friendly and not too formal.
- Use chart + callout when the pain is measured.

Avoid: decorative red accents when the content is neutral.

## Insight

Use when turning evidence into a finding.

- Use 3 insight circles/cards when there are parallel findings.
- Use a dark translucent panel over image when the insight is high-level or emotional.
- Use a bottom insight band when the slide first presents evidence then concludes.
- Use one bright accent phrase per insight.

Avoid: mixing insight and solution in the same card unless the layout explicitly maps evidence to opportunity.

## Solution / Strategy

Use when proposing direction.

- Use As-Is / To-Be comparison for clear improvement.
- Use pipeline/timeline when change happens through stages.
- Use central product mockup with side annotations for UI solution explanation.
- Use 3 feature cards for service principles or MVP pillars.
- Use dark mode for solution reveal or product walkthrough with a phone mockup.

Avoid: showing product screens without annotation. The showing way must explain what changed.

## Workflow / Journey / Process

Use when showing sequence, roles, or lifecycle.

- Use horizontal timeline for 3-5 stages.
- Use connected cards with arrows for operational flow.
- Use swimlane or left/right split when two actors interact.
- Use circular loop only for repeating lifecycle or ecosystem value.

Avoid: curved dotted connectors unless they clarify flow. Decorative connectors make slides harder to scan.

## Comparison / Positioning

Use when contrasting options or user segments.

- Use 2-column split for As-Is vs To-Be, current vs improved, user A vs user B.
- Use matrix/positioning map for behavioral segmentation.
- Use stacked comparison rows when comparing process length, friction, or steps.
- Use dark card against light background only when one side needs emphasis.

Avoid: using a matrix for simple yes/no differences.

## Product Feature / MVP

Use when explaining what the product provides.

- Use 3 feature columns with screenshots or icon cards.
- Use phone mockups as primary evidence for app flows.
- Use callout dots and dashed lines to annotate UI changes.
- Use a wide feature strip when describing client/service characteristics.

Avoid: too many UI screenshots. Show the screen state that proves the feature.

## Result / Impact

Use when showing outcomes.

- Use large metric cards for achieved results.
- Use dark result dashboards when numbers are the story.
- Use before/after bars when showing reduction or increase.
- Use green for improvement, blue for product/system impact, pink/red for risk reduced or problem fixed.
- Use a next-step/action-plan band when results lead to future work.

Avoid: result slides without a baseline or context label.
