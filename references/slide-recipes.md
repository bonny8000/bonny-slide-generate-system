# Slide Recipes

Use this file to map source material into concrete slide structures.

## Recipe Format

Each recipe defines:

- Intent: what the slide must accomplish.
- Best mode: light, dark, or mixed.
- Primary component: the main visual structure.
- Support components: secondary objects.
- Copy shape: recommended text structure.
- Validation: what must be true before delivery.

## 1. Portfolio Cover

Intent: introduce a project or deck.

- Best mode: light for research/report, dark for product/tech reveal.
- Primary component: title block.
- Support components: product mockup, project metadata chips, or one hero visual.
- Copy shape: project name, one-line positioning, role/timeline/tools.
- Validation: no card around the main title; the project signal is visible in the first viewport.

## 2. Section Divider

Intent: mark a new phase.

- Best mode: light for report structure, dark for insight/solution climax.
- Primary component: centered title block or full-bleed dark panel.
- Support components: phase chips or progress line.
- Copy shape: section label, one sentence on what changes now.
- Validation: sparse, no unnecessary cards.

## 3. Context / Background

Intent: explain why the problem matters.

- Best mode: light.
- Primary component: evidence card row or chart card.
- Support components: title block, source footer, small key band.
- Copy shape: headline with one highlighted context phrase, 2-3 evidence points.
- Validation: evidence supports the headline; sources are visible.

## 4. Desk Research

Intent: summarize external or market evidence.

- Best mode: light.
- Primary component: three evidence cards.
- Support components: chart card, source labels, bottom insight band.
- Copy shape: method/context line, three findings, one synthesized takeaway.
- Validation: each card has one metric or claim, not a paragraph.

## 5. Survey Result

Intent: show quantified user findings.

- Best mode: light, or dark for final result dashboard.
- Primary component: chart card.
- Support components: metric cards, interpretation chips.
- Copy shape: sample size + question, top results, interpretation.
- Validation: chart has labels, baseline, and source.

## 6. Interview Synthesis

Intent: show qualitative patterns.

- Best mode: light for report flow; dark for emotional finding.
- Primary component: quote card cluster.
- Support components: participant tags, repeated phrase highlight, insight band.
- Copy shape: research method, 3 quote patterns, repeated pain.
- Validation: repeated pattern is clear; quotes do not compete equally.

## 7. Pain Point

Intent: define what blocks the user.

- Best mode: light with red/pink accent, or dark for emotional pain.
- Primary component: pain point card triad.
- Support components: avatar marker, quote snippets, severity chip.
- Copy shape: pain label, symptom quote, root cause.
- Validation: every pain explains cause and consequence.

## 8. Insight

Intent: convert evidence into strategic meaning.

- Best mode: dark or strong mixed mode.
- Primary component: insight module.
- Support components: evidence note, implication line, minimal diagram.
- Copy shape: one decisive statement, 1-2 evidence anchors, implication.
- Validation: insight is not just a solution idea.

## 9. HMW / Opportunity

Intent: bridge research to solution.

- Best mode: light or mixed.
- Primary component: problem-to-opportunity bridge.
- Support components: key band, connector arrows, design principle chips.
- Copy shape: pain -> HMW -> opportunity.
- Validation: each opportunity maps to evidence.

## 10. Solution Concept

Intent: introduce the proposed direction.

- Best mode: dark for reveal, light for report clarity.
- Primary component: as-is/to-be comparison.
- Support components: feature stack, product mockup, key band.
- Copy shape: current gap, proposed mechanism, expected change.
- Validation: mechanism is specific enough to understand.

## 11. Product Feature

Intent: explain one feature.

- Best mode: light for functional explanation; dark for walkthrough.
- Primary component: phone mockup walkthrough.
- Support components: 2-3 annotations, feature stack, before/after screen.
- Copy shape: user scenario, feature behavior, user value.
- Validation: screenshot is readable and annotated.

## 12. User Flow / Journey

Intent: show sequence or service operation.

- Best mode: light for operational flow, dark for product process map.
- Primary component: workflow timeline.
- Support components: actor chips, stage cards, artifact labels.
- Copy shape: trigger, stages, handoff, outcome.
- Validation: no more than 5 stages unless split across slides.

## 13. Comparison / Benchmark

Intent: compare alternatives, competitors, segments, or before/after states.

- Best mode: light.
- Primary component: as-is/to-be comparison or positioning map.
- Support components: benchmark case cards, criteria rows, selected segment callout.
- Copy shape: comparison criteria, key difference, decision.
- Validation: each side uses parallel categories.

## 14. MVP / Feature Set

Intent: show what will be built first.

- Best mode: light.
- Primary component: feature stack.
- Support components: priority chips, product mockup, scope boundary note.
- Copy shape: MVP goal, three pillars, excluded or later items.
- Validation: feature titles are user outcomes, not only nouns.

## 15. Result / Impact

Intent: show what improved.

- Best mode: dark for executive impact, light for client report.
- Primary component: result dashboard.
- Support components: before/after bars, quote proof, next-step band.
- Copy shape: result headline, 2-3 metrics, baseline, interpretation.
- Validation: each metric has a period/source/baseline.

## 16. Appendix / Detail

Intent: preserve detail without slowing the story.

- Best mode: light.
- Primary component: dense table, source list, or screenshot grid.
- Support components: small title block, page marker.
- Copy shape: factual labels and references.
- Validation: treated as appendix, not core narrative.

## Deck Story Patterns

### UX Research Case Study

1. Cover.
2. Context/background.
3. Desk research.
4. User research method.
5. Interview synthesis.
6. Pain point.
7. Insight.
8. Opportunity/HMW.
9. Solution concept.
10. Feature walkthrough.
11. Result or next validation.

### Product Redesign Case Study

1. Cover.
2. Current product problem.
3. User evidence.
4. As-Is / To-Be.
5. Redesign principles.
6. Key flow.
7. Feature walkthrough.
8. Usability test.
9. Result.

### Strategy / Report Deck

1. Executive summary.
2. Background.
3. Data evidence.
4. Segmentation or positioning.
5. Opportunity areas.
6. Recommended direction.
7. Roadmap/timeline.
8. Measurement plan.

## Component Selection Matrix

- Need proof: evidence card or chart card.
- Need emotion: quote card or dark interview wall.
- Need synthesis: insight module or key band.
- Need transition: problem-to-opportunity bridge.
- Need improvement: as-is/to-be comparison.
- Need product behavior: phone mockup walkthrough.
- Need sequence: workflow timeline.
- Need options: positioning map or comparison rows.
- Need final value: result dashboard.
