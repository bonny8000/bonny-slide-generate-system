# Component System

Use this file before composing any Bonny V2 slide. Pick components by the content job first.

## 1. Title Block

Use for every slide except pure visual covers.

Anatomy:

- Eyebrow: category, method, phase, or section marker.
- Headline: one argument in CJK.
- Support line: English or concise context.
- Optional source/method chip.

Variants:

- Editorial left: default for research and report slides.
- Centered: section divider, insight, or cover.
- Split title: title left, metric/status right.
- Minimal top bar: dense dashboard or phone walkthrough.

Rules:

- Eyebrow uses accent color and `16-20px`.
- Main title uses `44-60px`.
- Support line uses muted text and `22-28px`.
- Highlight only one phrase in the headline.

Avoid:

- Two large titles.
- Decorative labels that do not identify content type.

## 2. Evidence Card

Use for desk research, survey findings, market background, or feature evidence.

Anatomy:

- Small label.
- One metric, chart, or screenshot.
- One short interpretation sentence.
- Source caption.

Variants:

- Metric evidence: large number + one-line proof.
- Chart evidence: bar/line/donut + annotation.
- Text evidence: title + 2 concise bullets.
- Screenshot evidence: cropped screen + caption.

Rules:

- Use 3 cards per row as the default.
- Card height should align across a row.
- Make one card visually dominant only if it is the key finding.
- Sources sit inside the bottom of cards or in a shared footer.

Avoid:

- Raw tables.
- Long paragraphs inside cards.
- Three different chart types in one row unless comparing methods.

## 3. Chart Card

Use when a number or relationship carries the slide.

Anatomy:

- Chart title.
- Chart body.
- Highlight annotation.
- Axis/baseline/source.

Variants:

- Before/after bars.
- Category bar comparison.
- Simple line trend.
- Donut share.
- Two-metric mini dashboard.

Rules:

- Active data uses semantic accent; inactive data uses gray.
- Use a callout label to explain the change.
- Keep chart labels larger than normal web dashboard labels because this is a slide.

Avoid:

- Overloaded chart legends.
- Low-contrast pastel chart labels.

## 4. Quote Card

Use for interview, user testing, VOC, or emotional pain.

Anatomy:

- Quote text.
- Participant or segment tag.
- Context metadata: age, role, scenario, task, or test condition.
- Highlighted repeated phrase.

Variants:

- Single hero quote.
- Three quote cards.
- Chat bubble cluster.
- Positive/negative feedback split.
- Dark interview wall.

Rules:

- Use quote cards to show patterns, not isolated anecdotes.
- Highlight repeated terms across quotes in the same accent.
- Include participant metadata only if it improves credibility.

Avoid:

- Five equal-weight quotes.
- Decorative quote marks that consume more space than the insight.

## 5. Pain Point Card

Use when defining what is wrong.

Anatomy:

- Pain label.
- User quote or observed symptom.
- Root cause or friction driver.
- Optional severity marker.

Variants:

- Three-card pain triad.
- Pain card with avatar/emoji marker.
- Pain to opportunity column.
- Measured pain with chart.

Rules:

- Use red/pink only for actual friction, warning, or negative result.
- The card must explain cause, not only symptom.
- Keep card titles concrete.

Avoid:

- Vague labels like "Problem 1".
- Cute characters on formal client/report slides.

## 6. Insight Module

Use when synthesizing evidence into a strategic finding.

Anatomy:

- Insight label.
- One highlighted statement.
- Evidence note or explanation.
- Optional implication line.

Variants:

- Insight trio.
- One large center insight.
- Bottom insight band under evidence.
- Dark cinematic insight panel.

Rules:

- Insight is not a feature. It should describe why users behave this way or what the system must account for.
- Use dark mode when the insight is the climax of a research section.
- Connect evidence to implication when possible.

Avoid:

- Mixing unrelated insights just to make three columns.
- Treating a recommendation as an insight without evidence.

## 7. Problem-To-Opportunity Bridge

Use when a deck transitions from research to solution.

Anatomy:

- Top: pain or evidence.
- Middle: connector arrow, bracket, or transformation line.
- Bottom: opportunity, HMW question, or design principle.

Variants:

- Three vertical columns.
- Left pain stack to right opportunity stack.
- Evidence row to bottom action band.

Rules:

- Each pain must map to one opportunity.
- Keep connectors simple and directional.
- Use blue/green for opportunity, red/pink/gray for pain.

Avoid:

- Decorative arrows with no semantic mapping.
- Opportunities that are just feature names.

## 8. As-Is / To-Be Comparison

Use for process, service, UI, or value improvement.

Anatomy:

- Left current state.
- Center transition marker.
- Right improved state.
- Bottom takeaway.

Variants:

- Two cards side by side.
- Table rows comparing criteria.
- Before/after chart.
- Current dark muted card and future accent card.

Rules:

- Left side should feel quieter or more constrained.
- Right side should show the specific improvement mechanism.
- Use equivalent categories on both sides.

Avoid:

- Comparing different levels of abstraction.
- Making the To-Be side only a slogan.

## 9. Workflow Timeline

Use for sequence, journey, project phase, service operation, or product flow.

Anatomy:

- Stage labels.
- Stage cards.
- Connector line/arrows.
- Actor or artifact labels when needed.

Variants:

- 3-5 horizontal stages.
- Vertical status journey.
- Swimlane for two or more actors.
- Loop for repeated lifecycle.

Rules:

- Use 3-5 stages on one slide.
- Show actor changes with lanes, not color alone.
- Use dotted connectors only for optional or indirect flow.

Avoid:

- More than 6 steps.
- Curved decorative connectors that reduce scanability.

## 10. Phone Mockup Walkthrough

Use for mobile product, app feature, or UI state explanation.

Anatomy:

- Phone mockup or product screenshot.
- 2-3 callout dots.
- Side annotation labels.
- Optional before/after mini-screen.

Variants:

- Hero phone centered.
- Two-phone before/after.
- Phone plus feature stack.
- Dark stage with white UI cards.

Rules:

- The screen must be readable.
- Callouts explain user value or interaction change, not obvious UI labels.
- Keep annotation lines short and non-overlapping.

Avoid:

- Too many app screens.
- Mockup without explanation.

## 11. Feature Stack

Use for MVP, feature set, service principles, or product pillars.

Anatomy:

- Section title.
- 3 feature rows or columns.
- Icon, screenshot, or small evidence element.
- User value line.

Variants:

- Three columns.
- Right-side stacked rows.
- Feature strip under product mockup.
- Priority row highlighted.

Rules:

- Use verbs or user outcomes as titles.
- Include what the feature changes for the user.
- Use icons only if they speed scanning.

Avoid:

- Feature names without value.
- Four or more equal features unless they are process steps.

## 12. Result Dashboard

Use for outcomes, final impact, test result, or business/product improvement.

Anatomy:

- Result headline.
- Large metric cards.
- Baseline or comparison period.
- Supporting chart or explanation.
- Next-step band if action follows.

Variants:

- Dark executive dashboard.
- Light client report result.
- Before/after metric comparison.
- Result plus quote proof.

Rules:

- Every metric needs a label and baseline.
- Use green for improvement, blue for product/system lift, red/pink for reduced risk or problem fixed.
- One large metric can dominate; secondary metrics should be smaller.

Avoid:

- Result numbers without source or period.
- Too many dashboard widgets.

## 13. Positioning Map

Use for market mapping, user segmentation, behavior grouping, or strategy focus.

Anatomy:

- Axis labels.
- Dots, regions, or segments.
- Highlighted target segment.
- Interpretation list.

Variants:

- 2x2 matrix.
- Scatter map.
- Venn/circle overlap.
- Segment cards plus map.

Rules:

- Axis labels must be meaningful opposites.
- Highlight one selected region or segment.
- Explain the decision, not only the placement.

Avoid:

- Matrix for simple yes/no comparison.
- Unlabeled axes.

## 14. Case Study Card

Use when introducing a project, case, benchmark, or reference.

Anatomy:

- Visual sample.
- Case title.
- Why it matters.
- Source/domain.
- Key takeaway or transferable pattern.

Variants:

- Single case card plus analysis.
- Three benchmark cards.
- Left visual, right notes.
- Dark selected-case panel.

Rules:

- Extract transferable pattern, not just aesthetic description.
- Use screenshots only if they are legible.

Avoid:

- Treating benchmarks as decoration.
- Missing source labels.

## 15. Key Band

Use for final takeaway, HMW, action principle, or section transition.

Anatomy:

- Short statement.
- Optional supporting line.
- Optional source or method tag.

Variants:

- Bottom band under evidence.
- Full-width center band.
- Dark band on light slide.
- Accent band as next-step callout.

Rules:

- Keep it one sentence.
- Use only when it changes interpretation or moves the story forward.

Avoid:

- Repeating the slide title.
- Long paragraphs in a band.
