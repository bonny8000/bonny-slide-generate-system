# 初稿習慣對照

AI 起稿和逐句翻譯時，常不自覺用上這些寫法。它們本身不算錯，台灣的文章裡也會出現「透過」「進行」。問題在於不分場合地用，讀者一眼認出套路，就不再細讀。

用法：成稿後照這份掃一遍。碰到左欄的寫法，先問中欄的問題。答得出來就留，答不出來就照右欄改。改完回頭核對意思有沒有變。

## 開頭與結尾

| 初稿常見 | 先問 | 可以怎麼改 |
| --- | --- | --- |
| 「好的，以下是為你撰寫的…」「當然可以！」 | 讀者要的是這句，還是後面的成稿？ | 直接給成稿或答案。 |
| 「在這個…的時代」「隨著…的發展」「近年來，…越來越受到重視」 | 刪掉這句，讀者少知道什麼？ | 從第一個有資訊的句子起筆。 |
| 「你是否也曾經…？」當開頭 | 讀者真的有這個疑問嗎？ | 直接說這篇能幫他做什麼。真有共鳴的情境，寫成一個具體場景。 |
| 「本文將介紹…」「以下將說明…」「接下來讓我們看看…」 | 預告之後，內容是不是緊接著就來？ | 刪掉預告。長文需要導覽時，用小標。 |
| 「總而言之」「綜上所述」「總結來說」加一段重述 | 這段有前文沒說過的東西嗎？ | 沒有就刪，收在最後一個有內容的句子。 |
| 「讓我們一起…」「相信…會更好」「未來值得期待」 | 這是讀者的感想，還是你替他下的？ | 刪掉，或換成讀者下一步能做的事。 |
| 「希望對你有幫助」「如有任何問題歡迎隨時詢問」 | 讀者不看這句會錯過什麼？ | 刪掉。真有後續管道，寫出管道。 |
| 成稿後附「主要調整如下」、逐項解釋改了哪些字 | 對方問了嗎？ | 沒問就不附。刪掉了帶資訊的句子，或有需要對方決定的事，才用一兩行說。 |

## 萬用詞

| 初稿常見 | 先問 | 可以怎麼改 |
| --- | --- | --- |
| 進行、做出、給予、加以＋動作名詞（進行討論、做出調整） | 後面那個詞自己能當動詞嗎？ | 「討論」「調整」。是方法或階段名稱時保留。 |
| 提供＋名詞（提供協助、提供支援） | 實際上做了什麼？ | 「協助你…」「可以…」。 |
| 打造、賦能、助力、驅動、引領、深耕 | 誰對誰做了什麼動作？ | 換成看得見的動作：「讓店家當天收到款項」。 |
| 提升、優化、強化、改善（沒有說多少） | 從多少變多少？哪一點變好？ | 寫出數字或具體差別。沒有根據就不寫。 |
| 確保、致力於、旨在 | 是已經做到，還是想做到？ | 做到了就寫做了什麼；是目標就寫「目標是…」。 |
| 體驗、解決方案、生態、場景、價值 | 換成一樣摸得到的東西是什麼？ | 「結帳流程」「這套工具」「三種用法」。 |
| 至關重要、不可或缺、扮演重要角色、關鍵的 | 少了它會怎樣？ | 寫出後果：「沒有備份，換手機時聊天紀錄會消失」。 |
| 非常、十分、極為、相當、高度 | 拿掉以後意思差多少？ | 多半可以拿掉，或換成事實。 |
| 多元、豐富、全方位、一站式、各式各樣、眾多 | 有幾種？是哪幾種？ | 寫數量或舉兩個例子。 |
| 無縫、輕鬆、簡單、直覺、強大 | 讀者怎麼驗證？ | 寫步驟數、時間或前後差別：「三個步驟完成」。 |
| 深入探討、全面解析、完整指南 | 內容真的做到了嗎？ | 寫這篇實際涵蓋什麼。 |
| 值得注意的是、需要注意的是、值得一提的是 | 後面那句自己站得住嗎？ | 刪掉引導語，把差異放句首。 |
| 可能、或許、某種程度上、一般來說、通常（疊用） | 到底哪一件事不確定？ | 留一個，放在不確定的那件事旁邊。 |
| 一個、一種、一些（照英文冠詞補上的） | 拿掉以後還通順嗎？ | 「是一個很好的選擇」寫成「是很好的選擇」。 |
| 們（使用者們、功能們、資料們） | 中文這裡需要標複數嗎？ | 多半不需要：「所有使用者」「各位老師」。稱呼人群的「同學們」「朋友們」可以留。 |
| 相關、等等、之類、方面（收尾用） | 省略掉的是什麼？ | 寫出來，或者刪掉。 |

## 套用句式

| 初稿常見 | 先問 | 可以怎麼改 |
| --- | --- | --- |
| 「這不是 A，而是 B」「不只是 A，更是 B」 | 真有人以為是 A 嗎？ | 沒有就直接說 B。有，先交代是誰這樣以為。 |
| 「不僅…更…」「不但…而且…」 | 後半真的比前半更進一層嗎？ | 只是並列就用「也」，或拆成兩句。 |
| 三個並排的形容詞或名詞（快速、安全、可靠） | 是剛好三項，還是湊成三項？ | 留說得出根據的。兩項或四項都可以。 |
| 「無論你是 A 還是 B，都能…」 | 這段文字的讀者是誰？ | 對著那一種讀者寫。確實有兩群人時，各寫一句各自的好處。 |
| 「透過…來…」「藉由…的方式」 | 「透過」後面是管道，還是動作本身？ | 是動作就從動詞起筆：「報名參加」。 |
| 「對於…來說／而言」「在…方面」「就…而言」「關於…」開頭 | 那個對象能直接當主詞嗎？ | 「對於新手來說，這個功能很實用」寫成「新手用得上這個功能」。 |
| 「讓…變得更…」「使得…能夠…」 | 直接說結果行不行？ | 「讓結帳變得更快」寫成「結帳更快」。 |
| 「當…的時候」「在…之後」處處都有 | 能不能縮成「…時」「…後」，或用逗號接？ | 「當你收到驗證碼時」寫成「收到驗證碼後」。 |
| 「…的部分」「…的動作」「做一個…」 | 拿掉以後少了什麼？ | 「付款的部分」寫成「付款」；「做一個確認的動作」寫成「確認」。 |
| 「為什麼？因為…」「結果呢？…」自問自答 | 讀者會在這裡發問嗎？ | 會，就留一次。不會，直接說原因。 |
| 「是時候…了」「說到底」「簡單來說」「換句話說」 | 前面是不是說得太繞？ | 把前面那句改清楚，刪掉這句。 |
| 「首先…其次…最後…」「第一…第二…第三…」 | 這幾件事有先後或並列關係嗎？ | 是步驟就編號。是論述就讓句子自己接。 |
| 「值得／可以／能夠／得以」＋動詞，一句裡疊兩個 | 一個夠不夠？ | 「可以讓你能夠」寫成「讓你」。 |
| 每句都有「我們」「你」「它」 | 主詞換了嗎？ | 沒換就省。 |

## 翻譯腔

| 初稿常見 | 先問 | 可以怎麼改 |
| --- | --- | --- |
| 「你的」「您的」每個名詞前都有 | 讀者會弄錯是誰的嗎？ | 「請輸入您的電子郵件以重設您的密碼」寫成「輸入電子郵件，重設密碼」。 |
| 被動句（被使用、被認為、被設計來） | 是誰做的？ | 把做事的人放句首，或用「由」「經」「受到」。無主詞句也可以：「檔案已刪除」。 |
| 「最…之一」 | 是在排名，還是只想說很重要？ | 「很常見的原因」「主要原因有三個，其一是…」。 |
| 「這是很重要的去…」「…是可能的」 | 誰要做什麼？ | 「請務必先備份」「可以離線使用」。 |
| 抽象名詞當主詞（這個功能的使用需要…） | 人能不能當主詞？ | 「要用這個功能，需要先…」。 |
| 長定語放在名詞前（那個你昨天上傳的沒有通過審查的檔案） | 能不能把名詞先叫出來？ | 「你昨天上傳的檔案沒有通過審查」。 |
| 「將會」「將要」「會將」 | 一個字夠不夠？ | 「會」或「將」。已排定的事可以直接寫時間：「明天開放」。 |
| 「和」「以及」「與」連接兩個分句 | 中文這裡用逗號行不行？ | 「打開設定，點選通知」。「並」「再」「然後」依關係選用。 |
| 「請」開在每一句步驟前 | 這是一連串步驟嗎？ | 編號後從動詞起筆。單獨一句請求時留「請」。 |
| 「如果你想要…，你可以…」 | 能不能縮短？ | 「要…，請…」「想…的話，…」。 |
| 「基於」「鑑於」「有鑑於此」 | 口語會怎麼說？ | 「因為」「所以」，或直接並列。 |
| 「…性」「…化」「…度」連著出現（可用性、個人化程度） | 用動詞或形容詞說一次是什麼？ | 「好不好用」「能照自己的習慣調整多少」。 |
| 專有名詞後補一串括號原文 | 讀者需要原文來辨認嗎？ | 需要就第一次出現時附，之後不重複。 |
| 語序照原文：結果在前、條件拖在句尾 | 中文讀者先需要哪一個？ | 條件、時間、範圍先說，結果放後面。 |

## 語氣

| 初稿常見 | 先問 | 可以怎麼改 |
| --- | --- | --- |
| 「非常抱歉造成您的不便」「感謝您的耐心等候」每則都有 | 這次真的造成不便嗎？ | 有就道歉一次，接著說怎麼處理。 |
| 驚嘆號收尾、「太棒了！」「恭喜！」 | 這件事值得慶祝嗎？ | 完成一般操作，說完成了什麼就好。 |
| 「請務必」「切記」「千萬不要」 | 做錯的後果是什麼？ | 寫出後果，讀者自己會小心。 |
| 聊天回覆寫成條列加粗的說明文 | 對方是在聊天，還是在要一份文件？ | 一兩句，先回答。 |
| 每句句尾加「喔」「呢」「唷」 | 拿掉以後會不會太硬？ | 一則留一個，放在提醒那一句。 |
| 「親愛的用戶您好」開頭的產品通知 | 這個產品平常這樣跟人說話嗎？ | 直接說事情。 |
| 對專家解釋基本概念，或對新手用術語 | 讀者已經知道什麼？ | 照讀者的程度增刪。 |
| 兩邊都說好：「各有優缺點，視需求而定」 | 對方問的是哪一種需求？ | 照他的情況給建議，再說什麼情況下選另一個。 |

## 介面文案

| 初稿常見 | 先問 | 可以怎麼改 |
| --- | --- | --- |
| 每個確認視窗都是「確定要…嗎？」或「是否…？」 | 這件事做了還能復原嗎？ | 一般的確認寫「要…嗎？」。「確定」留給復原不了的事。「是否」不用。 |
| 按鈕只有「確定」「取消」 | 只看按鈕，知道按下去會怎樣嗎？ | 換成動作：「刪除」「繼續編輯」。只需要看過的提示用「知道了」。 |
| 「…成功！」「操作成功」 | 讀者原本擔心會失敗嗎？ | 寫「已儲存」「已複製連結」。付款、送出申請這類才寫成功。 |
| 「很抱歉，發生錯誤」「糟糕！出了點問題」 | 讀者損失了什麼？ | 沒有損失就不道歉，直接說出了什麼事、怎麼辦。 |
| 「發生未知錯誤，請稍後再試」 | 真的什麼都不知道嗎？ | 寫出哪個動作沒完成、資料還在不在。 |
| 「暫無資料」「查無資料」 | 是本來沒有、還沒有，還是沒找到？ | 「沒有…」「還沒有…」「找不到…」，並寫出是什麼東西。 |
| 「請輸入您的…」當欄位名稱或提示 | 欄位名稱已經說了嗎？ | 欄位叫「電子郵件」，提示放格式或範例。 |
| 「您的帳號」「您的檔案」「您的設定」 | 會有人以為是別人的嗎？ | 多半省略。 |
| 「點擊這裡」「點此」當連結文字 | 只看連結文字，知道會去哪裡嗎？ | 連結放在說明去處的那幾個字上：「查看訂單」。 |
| 開關名稱是否定句（「不顯示預覽」） | 開啟以後是顯示還是不顯示？ | 改成肯定句，用預設值表達。 |
| 同一個動作出現「刪除」「移除」「清除」「刪掉」 | 它們做的是同一件事嗎？ | 是就統一；不是就照實際後果各用一個詞。 |
| 工具提示描述圖示的樣子 | 按下去會做什麼？ | 寫動作：「分享這個頁面」。 |
| 一個句子用變數拼起來（「{動作}{對象}成功」） | 換一組字還通順嗎？ | 每種情況各寫一句完整的話。 |

## 版面與標點

| 初稿常見 | 先問 | 可以怎麼改 |
| --- | --- | --- |
| 破折號「——」插入補充、製造停頓 | 逗號、括號或另起一句行不行？ | 多半可以。一篇留一兩處。 |
| 標題用「：」切兩半（主題：一句口號） | 哪一半才是讀者要的？ | 留那一半。另一半放副標。 |
| 每段配一個小標、每個重點加粗 | 讀者要靠它找東西嗎？ | 短文不需要小標。粗體只給期限、金額、名稱。 |
| 把連續的推論拆成條列 | 這幾點之間有「因為」「所以」「但」嗎？ | 有就寫回段落。 |
| 條列每項都是「**小標：**說明」 | 小標有沒有比說明多說什麼？ | 沒有就直接寫說明。 |
| 表情符號當項目符號或標題裝飾 | 這個場合的人平常這樣寫嗎？ | 社群貼文可以少量用。說明、公告、介面不用。 |
| 引號加在一般詞上表示強調（所謂的「效率」） | 是引述、專名，還是只想強調？ | 只想強調就拿掉。 |
| 半形逗號、句號、冒號混在中文裡 | — | 換成全形。 |
| 英文詞直接留在句子裡（進行 review、做 sync） | 讀者平常這樣說嗎？ | 團隊內部訊息可以。對外文案用中文說法，必要時括號附原文。 |

## 篇章

| 初稿常見 | 先問 | 可以怎麼改 |
| --- | --- | --- |
| 每段一樣長、一樣的結構（主題句、兩句說明、小結） | 內容真的這麼整齊嗎？ | 重要的多寫，次要的一句帶過。 |
| 每段最後一句是金句或小結 | 這句有新東西嗎？ | 沒有就刪。 |
| 把題目或對方的話再說一遍 | 讀者忘了自己問什麼嗎？ | 刪掉，直接回答。 |
| 列出所有可能性，不排序 | 哪一個最可能、最該先試？ | 先說那一個，其餘簡短帶過。 |
| 同一件事在開頭、中間、結尾各說一次 | 第二次有新資訊嗎？ | 留說得最清楚的那一次。 |
| 定義讀者早就懂的詞 | 讀者是誰？ | 刪掉。只解釋第一次出現的新詞。 |
| 給的資訊多，卻沒回答「所以我要做什麼」 | 讀者讀完能行動嗎？ | 加上下一步：動作、期限、管道。 |
| 補上需求沒給的原因、背景、認錯或補償（「這是我們的疏失」「返鄉人潮」） | 這件事是誰告訴你的？ | 沒有人說過就刪掉。覺得該補，放在成稿後面當建議。 |
| 摘要或下標題時拿掉「平均」「首次」「預計」「部分」 | 少了這個詞，結論有沒有變大？ | 變大就放回去。 |
| 標題只報好消息 | 內文有沒有「但」「不過」後面的那一半？ | 兩半都進標題，或把壞消息放副標。 |

## 改過頭

去掉套路時也會出錯。改完檢查這幾項。

- **刪到意思變了。** 拿掉「預計」「平均」「部分」「目前」，句子更俐落，主張也跟著變大。
- **短到讀不懂。** 為了簡潔省掉主詞、連接詞，讀者得自己猜誰做、為什麼。操作說明裡換人做事時，主詞要留。
- **口語過頭。** 把正式通知改得像聊天，金額、期限、權利義務讀起來不夠確定。
- **把常見詞當禁用詞。** 「透過視訊參加」「進行第二階段審查」是正常中文。先問那個詞交代了什麼，再決定留或刪。
- **每句都改。** 原稿讀得懂、意思準確的句子，留著。
