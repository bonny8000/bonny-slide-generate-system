# 介面元件的寫法

依元件查。每一類先說讀者在那一刻要知道什麼，再給句型。選稿偏好和通則在 [slide-copy.md](slide-copy.md#畫面上的介面文案)，介面常用詞在 [taiwan-usage.md](taiwan-usage.md#介面常用詞)，翻譯介面字串另見 [translation.md](translation.md)。

## 先看這段字出現在哪裡

- **短字串離開畫面就有好幾種意思。** 「5 分鐘」可以是已經過了多久、還剩多久，或一段長度。動筆前確認它在哪個畫面、旁邊有什麼、什麼時候出現。拿到的是字串表，就看鍵名和開發者註解；看不出來就問。
- **同一個詞當動作和當狀態，寫法不同。** 開關旁的說明寫現在的狀態：「已開啟」「已關閉」。可以按的選項寫動作：「開啟」「關閉」。「連線」是按鈕，「已連線」是狀態，「正在連線…」是進度。
- **一個元件有幾種狀態，就寫幾則。** 預設、進行中、空的、失敗、成功各一則，放在一起讀，確認用詞前後一致。

## 按鈕與標籤

- **按鈕動詞開頭，兩到六個字。** 畫面上只有一個對象、不會弄錯時，單一動詞就夠：「儲存」「刪除」「下一步」。補救動作、有兩個相近的動作，或按下去有後果時，補上對象：「重選結束日期」「儲存草稿」「刪除帳號」。
- **不想做的選項也要是一句人話。** 「暫時不要」「略過」「知道了」「不用了」。只有「取消」和「確定」時，讀者得回頭讀標題才知道在取消什麼。
- **「知道了」用在只需要看過的提示，「確定」用在會執行動作的地方。** 按下去什麼都不會發生，就不要寫「確定」。
- **標籤是名詞，不加「請」和句號。** 欄位叫「手機號碼」，不叫「請輸入您的手機號碼」。
- **選單和分頁用同一種詞性。** 全是名詞（「帳號」「通知」「隱私」），或全是動詞片語（「管理帳號」「設定通知」）。

## 動作和對象的搭配

動詞跟著對象走。同一個英文動詞，換了對象就要換中文。

| 對象 | 做 | 反過來 |
| --- | --- | --- |
| 開關、功能 | 開啟、啟用 | 關閉、停用 |
| 檔案、訊息、帳號 | 刪除 | 還原、復原 |
| 清單裡的項目、成員、裝置 | 移除 | 加入、新增 |
| 紀錄、快取、搜尋欄 | 清除 | — |
| 設定、密碼 | 重設 | — |
| 上一步操作 | 復原 | 重做 |
| 備份、原廠設定 | 還原 | — |
| 使用者、來電 | 封鎖 | 解除封鎖 |
| 對話、通知 | 靜音 | 取消靜音 |
| 對話、項目 | 釘選 | 取消釘選 |
| 對話、郵件 | 封存 | 取消封存 |
| 訂閱、預約、訂單 | — | 取消 |
| 追蹤對象 | 追蹤 | 取消追蹤 |
| 藍牙裝置 | 配對 | 解除配對 |
| 網路、裝置 | 連線 | 中斷連線 |
| 群組 | 加入、建立 | 退出、解散 |
| 通話、會議 | 加入、開始 | 離開、結束、掛斷 |
| 帳號 | 登入 | 登出 |
| App、擴充功能 | 安裝 | 解除安裝 |
| 草稿、變更 | 儲存 | 捨棄 |
| 螢幕、裝置 | 鎖定 | 解鎖 |

- **「刪除」和「移除」不互換。** 東西會消失用「刪除」。只是從這裡拿掉、別處還在，用「移除」。
- **「開啟／關閉」和「啟用／停用」各管一種。** 讀者隨手切換的開關用「開啟／關閉」。要先設定、有前置條件或由管理員控制的功能用「啟用／停用」。同一個功能前後用同一組。
- **「取消」前面沒有動詞時，只用在中止進行中的事。** 要反轉一個狀態，寫成「取消＋動詞」或「解除＋動詞」，並在整個產品裡固定。
- **點、按、滑各用一個詞。** 「點一下」「輕觸」「點選」「按一下」擇一，全產品統一。觸控和滑鼠共用的說明，用「選取」或直接寫動作。

## 確認視窗

- **標題用「要…嗎？」問讀者正在決定的事。** 「要捨棄草稿嗎？」「要移除這位成員嗎？」動詞和按鈕上的一樣。
- **「確定要…嗎？」留給無法復原的事。** 每個確認都寫「確定」，真正危險的那一個就不顯眼了。
- **不用「是否」。** 「是否刪除？」讀起來像表單欄位，不像在問人。
- **內文一句說後果，寫出會消失的東西和範圍。** 「這則對話的所有訊息會從你的所有裝置刪除」。復原不了，就明說「刪除後無法復原」。只有「此操作無法復原」而沒說會失去什麼，讀者還是不知道要不要按。
- **主要按鈕重複標題的動詞，另一個按鈕寫留下來會怎樣。** 「刪除」和「取消」；離開編輯畫面時是「捨棄」和「繼續編輯」。
- **動作本身就是「取消」，或內文還提到要取消別的東西時，另一個按鈕不寫「取消」。** 取消預約的視窗用「取消預約」和「保留預約」。刪除帳號的內文提到要另外取消訂閱，按鈕就用「刪除帳號」和「保留帳號」。
- **不需要確認的事不問。** 可以復原的動作，做完給一則附「復原」的提示，比事前多問一次好。

## 錯誤訊息

- **做不成的事寫「無法＋動作」。** 「無法儲存使用者名稱」。「…失敗」適合當狀態標籤：「上傳失敗」「付款失敗」。
- **一句說出了什麼事，一句說現在怎麼辦。** 「訊息沒能送出，請檢查網路連線後再試一次」只知道其中一半，就寫知道的那一半。
- **原因是讀者的輸入時，直接說要什麼。** 「密碼至少要 8 個字元」比「密碼格式錯誤」有用。
- **原因在系統這一邊時，說清楚不是讀者的問題，以及資料還在不在。** 「我們這邊出了狀況，你填的內容已保留」
  下一步另起一行「請稍後再試」
- **「請」放在要讀者做的那一句開頭，一則一個。** 說明狀況的句子不加「請」。
- **不道歉，除非真的造成損失。** 一般的操作錯誤不需要「很抱歉」。扣了款、丟了資料、讓人等很久，才道歉一次。
- **錯誤代碼放最後，供回報用。** 「（錯誤代碼：E102）」。
- **「再試一次」是按鈕上最常見的說法。** 空間很小時用「重試」。

## 空狀態與找不到

四種「沒有」各有說法：

| 情況 | 寫法 | 例 |
| --- | --- | --- |
| 本來就可能沒有 | 沒有… | 沒有可用的更新 |
| 還沒開始用，之後會有 | 還沒有…、尚未… | 還沒有收藏的文章 |
| 找過了，沒找到 | 找不到… | `找不到「發票」的相關結果` |
| 某個狀態沒有成立 | 未… | 未連線、未選取任何項目 |

- **空狀態接一個能做的事。** 「這裡會顯示你收藏的文章，看到喜歡的文章，點一下書籤就能收藏」沒有事可做時，一句說明就夠。
- **搜尋沒有結果時，把搜尋詞放回句子裡，再給一個方向。** `找不到「發票」的相關結果` 下一行 `可以換個關鍵字再找找`
- **不寫「暫無資料」「查無資料」。** 寫出是什麼東西沒有。

## 權限請求

- **系統詢問用「要允許…嗎？」** 例如 `要允許「地圖」使用你的位置嗎？`，App 名稱加「」。
- **請求之前或同一則裡，說要拿來做什麼。** 「開啟相機權限後，才能掃描 QR Code」只寫「需要相機權限」，讀者不知道拒絕會少什麼。
- **說清楚範圍和時間。** 「只在使用 App 時」「僅限這一次」「隨時可以在設定裡關閉」。
- **系統視窗的按鈕是「允許」和「不允許」。** 不用「同意」「拒絕」，那是條款的說法。系統視窗的字由各平台提供，內文提到時照該平台實際顯示的字。
- **App 自己的說明畫面放在系統視窗之前，按鈕用「繼續」和「暫時不要」。** 讀者按了「繼續」，才跳出系統的詢問。
- **被拒絕以後，說怎麼再打開，不責怪。** `相機權限目前關閉。要掃描的話，請到「設定」開啟。`

## 設定項目與開關

- **項目名稱是名詞或短動詞片語，讀得出開了會怎樣。** 「自動播放影片」「顯示已讀時間」。
- **避免否定的開關名稱。** 「不顯示預覽」開啟以後到底顯不顯示，要想兩次。寫成「顯示預覽」，預設關閉。
- **說明寫開啟後會發生什麼，不重複名稱。** 名稱是「自動備份」，說明寫「連上 Wi-Fi 時，每天備份一次照片」。名稱已經說完開啟時的行為，而且預設是開啟，說明就寫關閉後會怎樣。
- **有代價就寫出代價。** 「較耗電」「會使用行動數據」。
- **狀態摘要用「已…」或直接寫目前的值。** 「已開啟」「每天晚上 10:00」「3 個裝置」。
- **由讀者自己選的選項，可以用「我」。** 「誰可以看到我的電話號碼」「我很熟悉」。這是讀者在說話；系統對讀者說話的句子仍然用「你」或省略。
- **不能改的設定，說是誰決定的。** 「這項設定由管理員控管」。

## 進度、完成與提示訊息

- **進行中寫「正在＋動作…」。** 「正在上傳…」、`正在連線到「客廳喇叭」…`。空間小用「上傳中…」。同一個產品擇一。
- **會等超過幾秒，就說要多久或做到哪裡。** 「正在匯出，約需 1 分鐘」「已上傳 3 個，共 8 個」。
- **做完用「已＋動詞＋對象」。** 「已儲存」「已複製連結」「已開啟藍牙」。不寫「成功」，除非讀者原本擔心會失敗（付款、送出申請）。
- **可以反悔的動作，提示裡附「復原」。** 「已封存 1 則對話　復原」。
- **提示訊息一行，不加句號。** 會自己消失的訊息，不放讀者非看不可的事。
- **一批裡有成功有失敗，兩邊都寫。** 「已匯入 48 筆，2 筆格式不符」。

## 通知與推播

- **標題寫發生了什麼事，內文補一個細節或下一步。** 標題「包裹已送達」，內文「放在一樓管理室，請於 3 天內領取」。
- **誰做了什麼，人放句首。** 「小安回覆了你的留言」。
- **鎖定畫面上別人也看得到。** 金額、驗證碼、訊息內容要不要顯示，照產品的隱私設定；不確定時寫「你有一則新訊息」。
- **不用通知做沒有時效的宣傳。** 讀者關掉通知以後，重要的那一則也收不到。
- **標題與內文都不用句號**　結果和下一步可以分行，直問讀者時保留問號

## 工具提示與無障礙標籤

- **只有圖示的按鈕，提示寫它會做的動作。** 「分享這個頁面」「縮小」。不描述圖示的樣子（「紙飛機圖示」）。有快速鍵就附在後面：「縮小（Ctrl+-）」。
- **提示不重複畫面上已經有的字。** 按鈕上寫了「分享」，提示就補它沒說的事，或不放提示。
- **無障礙標籤寫「這是什麼＋現在的狀態」。** 「顯示密碼」「隱藏密碼」隨狀態切換；「通知，已開啟」「第 2 頁，共 5 頁」。元件的類型（按鈕、連結）由系統念，標籤裡不必再寫。
- **圖片的替代文字寫讀者少了這張圖會漏掉的資訊。** 示範操作的截圖寫出步驟和位置。純裝飾的圖留空。不用「圖片：」「一張…的照片」開頭。
- **標籤念出來要聽得懂。** 「%」「/」「→」放在標籤裡，換成「百分之」「共」「前往」。

## 新手引導

- **一個畫面說一件事，標題是讀者能得到的東西。** 「把常用的分頁釘在最前面」。
- **說明一兩句，接一個動作。** 前幾頁是「下一步」和「略過」，最後一頁是「開始使用」。最後一頁以前，「略過」每一頁都在。
- **問讀者問題時，選項寫成讀者的話。** 「我用過類似的工具」「我是第一次用」。
- **不在第一個畫面要權限和個人資料。** 等讀者用到那個功能，再說明並請求。
- **功能介紹寫怎麼用，不寫形容詞。** 「長按訊息，可以回覆或轉寄」。

## 變數、數量與時間

- **會帶入名稱的變數，用「」包起來。** `正在連線到「{裝置名稱}」…`。名稱裡有空格、英文或奇怪的字時，讀者才分得出哪一段是名稱。人名和數字不必加。
- **數字後面接量詞。** 「{count} 個項目」「{count} 則訊息」「{count} 位成員」。同一種東西全產品用同一個量詞。
- **中文沒有單複數，「一個」和「多個」併成一句。** 只有當數量是 1 時要說的事不一樣，才分開寫。字串用 ICU 格式時，中文只有 `other` 這一類，`one` 分支不會被用到；數量是 1 的那一句要寫成 `=1`。「還可以再試 {n} 次」；剩最後一次時：「還可以再試 1 次，再輸入錯誤就要聯絡電信業者解鎖」
- **不用變數拼出句子。** 「{動作}{對象}成功」這種寫法，換一組字就不通順。每種情況各寫一句完整的話。
- **有變數的句子，把變數各放進最長和最短的值念一次。** 名字很長、數字是 0、數字是 1 都要通順。0 的時候通常要另一句：「沒有新訊息」。
- **時間變數放在動詞前面。** 「3 分鐘前更新」「將於 5 分鐘後開啟」「還剩 2 天」。
- **相對時間由近到遠換單位。** 「剛剛」「5 分鐘前」「2 小時前」「昨天」「3 天前」，再遠就寫日期。未來用「…後」：「10 分鐘後」「明天」。
- **「X of Y」先分清楚是位置、進度還是比例。** 位置：「第 2 頁，共 5 頁」。進度：「已下載 3 個，共 8 個」。比例：「8 個 App 中有 3 個可存取位置」。
- **引出清單的句子用冒號收尾。** 「這個 App 將可以：」。

## 稱呼

- **「你」或「您」，整個產品只用一個。** 兩種都有產品在用，沒有哪一種比較對。混用才是問題。
- **「你的」大約有一半可以省。** 「檢查網路連線」不必寫成「檢查你的網路連線」。會弄錯是誰的東西時才留。
- **產品自稱時用名稱或「我們」，一份文案擇一。** 系統自動做的事不必有主詞：「已自動儲存」。
- **不寫「親愛的用戶」「小編」。** 介面不是信件，也不是社群貼文。

## 標點與長度

- **按鈕、標籤、選單、標題不加句號。**
- **問句保留問號。** 「要捨棄草稿嗎？」省掉問號，掃過去會讀成一句陳述。
- **按意思安排多行文字**　先寫目前狀態，再寫讀者能做的事，兩者有不同條件時分行
- **驚嘆號幾乎用不到。** 恭喜、歡迎可以用一個。錯誤和警告不用。
- **刪節號只表示進行中或後面還有。** 「正在載入…」「更多…」。
- **中文字數大約是英文字元數的四成，但每個字寬一倍，佔的寬度差不多。** 英文版放得下，不代表中文版一定放得下；按鈕和分頁要實際放進去看。
- **太長時先刪稱呼、「請」和重複的名詞，再刪說明，最後才縮動詞和對象。**
